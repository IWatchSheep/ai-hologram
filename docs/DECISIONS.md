| D-007 | 2026-10-19 | Coordinates are (x, y) with x = column left→right and y = row top→bottom; walls stored row-first as `walls[y][x]`. Worlds are read and printed using the 7-character text format in plan 3.5. | Matches how the text layout looks on screen; one format for input, output, and tests. | (row, column) pairs; a separate file format. | Owner |
| D-008 | 2026-10-19 | Movement rules are a pure function `applyAction(const WorldState&, Action)` returning a new state; the `Environment` class is the only holder of the true state. | The same kind of function can later be used for predictions without changing the real world; keeps "what I think" separate from "what is" (Brief Stage 2). | Rules as methods that change the environment directly. | Owner |
| D-009 | 2026-10-19 | Tests are split into several files sharing a `TestCounter`; checks are counted automatically; the CTest test is renamed `correctness_tests`. Every attempted action, including a blocked one, counts as a step. | The test suite now covers several components; a hand-typed count could become wrong. Counting blocked steps keeps step counts honest for later comparisons. | Keep one test file; count only successful moves. | Owner |
| D-010 | 2026-10-19 | *(v1.1)* One validity definition, `isValidWorld` (plan 3.6), used by `parseWorld` and checked at the top of `applyAction`. Invalid states produce the outcome `InvalidState` with the state unchanged. Positions outside the grid are treated as walls by `isWall`, which never reads outside the array. | Directly constructed states (tests now, beliefs later) must not cause crashes or out-of-bounds reads; a faulty belief that describes an impossible world should be reported clearly. Kept to one check, not a validation framework. | Trust callers without checking; exceptions; assertions that stop the program. | Owner |
| D-011 | 2026-10-19 | *(v1.2)* Copilot appends a handoff note after each piece of work to `results/notes_from_github_copilot/Response_from_Github_copilot.txt` (rule 2f, an exception to 2b). Copilot may not rename, move, or delete files unless a plan lists the change. | Makes Copilot's reports easy to pass on for review. On 2026-10-19, while this file was being set up, `docs/chatgpt_reply.txt` was renamed and the rename silently rewrote mentions of it in three approved files, including the tagged Stage 0 plan; all of it was reverted before any commit. | Copying Copilot's chat replies by hand; allowing renames with review afterwards. | Owner |
| D-012 | 2026-10-19 | Add rule 2g to `.github/copilot-instructions.md`: Copilot puts CLion's MinGW folder on the PATH before running programs or CTest, and never changes link settings, adds static linking, or copies DLLs to work around the missing-DLL error. | Copilot's own test runs repeatedly hit the missing-DLL error (0xc0000135) during Stage 1; a permanent rule prevents the pop-ups and stops anyone "fixing" an environment problem by changing the build. | Repeat the instruction in every Copilot request; allow link-setting changes. | Owner |
| D-013 | 2026-10-19 | Create `docs/copilot_prompts/` and save every instruction given to GitHub Copilot there, from Stage 2 onwards, named by stage and sub-stage. | The repository history then shows exactly what Copilot was asked to do at each step, not only the code it produced. | Keep prompts only in chat; keep them outside the repository. | Owner |
| D-014 | 2026-10-19 | A reasoner's belief is a separate type, `Belief`, wrapping a `WorldState`; only `Environment` holds the true state. | The compiler then prevents "what I think" being used as "what is" (Brief Stage 2). | Use `WorldState` for both. | Owner |
| D-015 | 2026-10-19 | `WorldModel` predicts by applying a replaceable `ActionModel` (`std::function`), defaulting to the true rules `applyAction`. | Lets a faulty action model (F3) be supplied later without a class hierarchy; keeps prediction separate from the true world. | Hard-code `applyAction`; an abstract base class with subclasses. | Owner |
| D-016 | 2026-10-19 | Every prediction is paid for through one `BudgetCounter` (one model evaluation each); when exhausted, `predict` returns no prediction instead of throwing. | Enforces equal computational budgets (Brief 11.5.3, rule 13d) and the no-exceptions rule (D-010). | Count predictions separately in each component; throw when over budget. | Owner |
| D-017 | 2026-10-19 | `compareStates` reports every difference in a fixed order (agent, object, destination, then walls row by row); a prediction matches only if outcomes are equal and no state differences exist. | A complete and stable report makes mismatches easy to read, test, and log. | Report only the first difference; compare outcomes only. | Owner |
| D-018 | 2026-10-19 | The Stage 2 demos replace the belief with the observation after each step, and say so in the output. This is a demonstration shortcut, not a correction policy. | Keeps Stage 2 free of reasoning; belief correction is a Stage 3 decision governed by Brief 4.5 and protocol Phase B. | Implement a correction rule now. | Owner |
| D-028 | 2026-10-19 | From sub-stage 3a follow-up 1, the coding assistant is **Cursor** (run inside CLion), replacing GitHub Copilot. JetBrains Junie may replace it later under the same rules. Every rule addressed to Copilot applies to whichever assistant is used, and each prompt says so. Two files are added: `.cursor/rules/ai-hologram.mdc`, always-applied rules that point to `.github/copilot-instructions.md`; and `.cursor/cli.json`, which allows only build and test commands without asking and blocks all git commands, deleting, moving or renaming files, and writing to `docs/`, `.github/`, `.cursor/`, `LICENSE` and `.gitignore`. The handoff-notes file and `docs/copilot_prompts/` keep their names (D-011). D-019 to D-027 remain reserved for sub-stage 3f (STAGE_03.md Section 8). | The owner's GitHub Copilot credits ran out, and a paid upgrade was not available. The project rules must travel with the tool, and the owner should not need to approve routine commands or watch for unwanted Git operations. | Keep using Copilot; repeat the rules in every prompt without project files; let the assistant run every command. | Owner |
| D-019 | 2026-10-19 | C1 and C0 are built from plain structs and free functions in `src/agent/`. The agents' state is a plain struct, so tests can build any state directly. There is no inheritance. | Keeps the code testable and readable for a beginner (Brief 8.2), and keeps the no-inheritance rule (D-010). | An agent base class with C0 and C1 subclasses. | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-020 | 2026-10-19 | The planner is a standard A* over the agent's own belief. It tracks the best *g* per state, replaces a path when a shorter one is found (reopening closed states), skips outdated queue entries, and accepts the goal when it is taken from the queue. Ties are broken by (*g* + *h*, *h*, entry number). The heuristic is admissible and consistent when nothing is overridden. The fallback chooses the best discovered state by (*h*, best *g*, discovery number). | Guarantees shortest plans when the search finishes, which makes a strong baseline (Brief Stage 3), and is deterministic. ChatGPT's review of plan v1.0 showed that accepting the goal when generated was not guaranteed shortest; the reference implementation confirmed this on 86 of 3,000 layouts. | Breadth-first search (shortest, but expensive); greedy best-first (cheaper, not shortest); goal accepted when generated (plan v1.0; not guaranteed shortest). | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-021 | 2026-10-19 | A per-step prediction cache allows free reuse of an identical prediction (same walls, positions, action and model) within one decision step. Variant predictions are never cached. A **reserve** (1 committed prediction + 1 V2 alternative per pending wall, object or model correction) is protected from every optional evaluation. If no committed prediction can be made, C1 takes no world action and safe-stops. | Implements protocol Phase B 10.7 "reuse" exactly. The reserve guarantees that C1 never acts without a checked prediction, and can test its pending corrections. | No cache (wasteful); caching across steps (not allowed by Phase B); a reserve covering only the committed prediction (pending corrections could never be tested at a tight budget). | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-022 | 2026-10-19 | Belief candidates from one mismatch are verified **together** with one shared re-prediction. A `model(a)` candidate's only correction is "use the standard rule for *a*". | The candidates come from exact evidence lookups, so applying them together reproduces the observation when they are right. In Experiment 1 the world rules are fully known (Phase B 11.4). | Verifying each candidate alone (fails when two elements are wrong); learning a new model (out of scope). | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-023 | 2026-10-19 | In Stage 3, active tests are planned only for **wall** corrections. Object and action-model corrections are verified when a later committed prediction discriminates. | Phase B 11.5 says C1 *may* choose an active test. A wall test is simple and always safe (moving into a wall). An object's old value soon stops referring to the present, and a model test needs a safe push. | Active tests for every element type (more code; ill-defined for objects). | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-024 | 2026-10-19 | An exhaustive search (for a consequence surprise) must finish within one decision step's budget. It is not continued over several steps in Stage 3. **Accepted by ChatGPT as a documented simplification. It may reduce C1's ability to notice F4 at tight budgets, and this limitation must be kept in every report of Experiment 1.** | Phase B 11.4 B allows, but does not require, multi-step completion. One-step searches are much simpler (Phase B 12.7.4). | Keeping search state across steps. Any later change would follow the Phase A pilot rules (9.2–9.4): it may be made only because something does not work, never because it favours any condition. | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-025 | 2026-10-19 | After a mismatch in which the belief matched the record, so that `model(a)` is suspected, the footprint is updated **at once**. If V1 later fails, the update is logged as unexplained. | The belief before the action was confirmed by the record, so the world's change must be taken in to continue. Found by the reference implementation, where omitting it made every later prediction wrong. | Waiting for V1 before updating (the belief stays stale and causes false mismatches). | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-026 | 2026-10-19 | When C0 has no plan and no fallback action, it takes the first action its own model predicts as Moved or Pushed, otherwise North. C0 has no safe stops. | Keeps C0 deterministic and naive. The run always progresses to an outcome (Phase A 5.1). | Letting C0 stop (it has no safe stops in Phase B 11.8). | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
| D-027 | 2026-10-19 | Stage 3 code takes B, S_max, T_max and T_v as parameters. The demos use illustrative values (200, 5, 100, 3), and the program says so. | The real values are Phase C decisions. Hard-coding them would risk silently fixing protocol numbers. | Hard-coded constants. | Owner (STAGE_03.md v1.2, approved after review by ChatGPT) |
